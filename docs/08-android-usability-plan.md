# Android 里程碑 5.4：易用性优化方案

> 实施状态：已完成。Debug 自动化、签名 Release 覆盖安装与真机测试均已通过。基线版本为内部 Release 0.1.0。目标是让高频下载流程更短、更清楚、更容易恢复，不增加账号、云端或复杂导航。

## 0. 实施结果（2026-09-17）

已完成：

- 粘贴按钮写入单个链接后立即分析；系统分享仍自动分析但不自动下载。
- 紧凑 URI 输入、键盘“前往”分析、整行清晰度选择和单一状态区域。
- 分析、下载、保存三类失败阶段及对应重新分析/重试下载入口。
- Worker 返回 URI、文件名、相对路径和 MIME 类型；完成页支持打开视频、查看位置和再次下载。
- 完成通知直接尝试打开视频，文件夹定位不受支持时回退到系统文件选择器。
- 私有轻量存储保存活动 Work UUID、源链接和标题，App 重建后重新订阅 WorkManager 状态。
- `testDebugUnitTest assembleDebug` 已通过，默认产物仍为 `arm64-v8a`。

验收结果：签名 Release 已成功覆盖安装，5.4 主流程真机测试通过。Instagram 继续受源站登录要求限制。

## 1. 目标与边界

里程碑 5.4 聚焦一个主流程：

```text
分享或粘贴链接 → 分析 → 选择清晰度 → 下载 → 打开视频或查看位置
```

目标：

- 系统分享进入 App 后，最多两次主动点击完成下载并打开视频。
- 用户点击“粘贴”后立即分析，不再要求额外点击“分析链接”。
- 下载完成后能直接打开视频，并能查看或获知保存位置。
- 错误状态提供明确的恢复动作，而不是只显示错误文本。
- App 旋转、退到后台或进程被系统回收后，重新打开仍能恢复当前 WorkManager 任务。
- 继续保持单页、黑白灰、48dp 以上触控目标和本地处理。

本轮不做：

- 完整下载历史、Room 数据库和复杂任务管理器。
- 多任务并发队列和批量账号下载。
- 用户账号、云同步、遥测或远程配置。
- 底部导航、内置浏览器、封面瀑布流和复杂动画。
- 新平台接入或 Threads 解析范围扩张。

## 2. 开发范围与优先级

### P0：缩短输入与分析流程

1. 用户主动点击粘贴按钮后，将剪贴板中的单个 URL 写入输入框并立即调用分析。
2. 系统 `ACTION_SEND` 继续保持自动分析，但绝不自动开始下载。
3. URL 输入框从至少三行改为一至两行，长链接允许横向或尾部省略显示。
4. 输入框使用 URI 键盘类型和“分析/前往”IME 操作；键盘操作与“分析链接”按钮行为一致。
5. 保留手动输入和“分析链接”按钮，避免自动分析用户尚未输入完成的内容。

验收：粘贴路径从三次操作降为两次操作：点击粘贴、点击下载。

### P0：优化格式选择与状态反馈

1. 清晰度选项整行可点击，不仅单选圆点可点击；使用 `selectable` 和正确 RadioButton 语义。
2. 默认继续选中分析结果中的推荐格式，不额外弹窗确认。
3. 输入错误只在输入框附近显示；分析、下载和完成状态归入媒体/下载卡片，删除重复状态卡片。
4. 下载进度在同一卡片中同时显示百分比、进度条和取消操作。
5. 分析或下载进行中禁用会产生重复任务的操作，并保留明确加载反馈。

验收：任一错误或状态在同一屏幕只出现一次；所有触控区域至少 48dp，相邻操作至少间隔 8dp。

### P0：下载完成后的操作

完成状态改为：

```text
下载完成
文件名.mp4
Movies/Video Get

[打开视频]  [查看位置]
             [再次下载]
```

实现要求：

1. `DownloadWorker` 成功结果返回 `contentUri`、`displayName` 和 `relativePath`，不再只返回 URI 字符串。
2. “打开视频”使用 MediaStore `content://` URI 和 `ACTION_VIEW`，添加只读 URI 授权，并捕获没有播放器的情况。
3. “查看位置”采用尽力而为策略：优先请求系统文件管理器定位 `Movies/Video Get`；不支持文件夹定位的设备回退到系统文件选择器，并始终显示可复制的相对路径。
4. “打开视频”为主要操作；“查看位置”和“再次下载”为次要操作。
5. 下载完成通知点击后优先打开视频；若系统没有可处理的播放器，则打开 App 的完成状态。

Android 没有跨厂商完全统一的“打开文件夹”接口，因此“查看位置”不能作为唯一入口，“打开视频 + 显示路径”必须始终可用。

### P0：错误恢复动作

将错误归类并映射到操作：

| 状态 | 主提示 | 操作 |
|---|---|---|
| URL 无效 | 链接格式不正确 | 清空链接 |
| 分析超时/网络中断 | 网络连接失败 | 重新分析 |
| 内容要求登录 | 该内容需要登录 | 更换链接 |
| 没有视频 | 未找到可下载视频 | 更换链接 |
| 下载中断 | 下载未完成 | 重试下载 |
| 存储写入失败 | 无法保存文件 | 重试或打开存储设置 |

ViewModel 保存结构化失败阶段 `analyze | download | save`，UI 根据阶段显示恢复按钮。底层异常仍写入脱敏日志，但不直接作为主要用户文案。

### P1：恢复当前下载任务

当前 `activeWorkId` 只存在内存中，App 进程重建后界面无法重新订阅任务。里程碑 5.4 采用单活动任务恢复，不引入完整历史数据库：

1. 创建 WorkRequest 时加入固定标签和请求 ID，并把当前 Work UUID 保存在 App 私有轻量存储中。
2. `MainViewModel` 初始化时读取 UUID，通过 `getWorkInfoByIdFlow` 重新观察 `ENQUEUED`、`RUNNING` 和终态。
3. 请求快照保留标题、源 URL、格式标签以及结果展示所需字段，终态确认后再按清理策略删除。
4. 恢复时显示“等待网络”“正在下载”“正在处理”或“下载完成”，不能退回空白首页。
5. 取消后清除活动任务引用；失败时保留足够信息供用户点击“重试下载”。

本阶段仍只允许一个前台活动下载，避免引入队列 UI 和并发控制复杂度。

## 3. 状态与数据调整

建议新增：

```kotlin
data class CompletedDownload(
    val contentUri: String,
    val displayName: String,
    val relativePath: String,
)

enum class FailureStage {
    ANALYZE,
    DOWNLOAD,
    SAVE,
}
```

`HomeUiState` 已增加：

- `completedDownload: CompletedDownload?`
- `failureStage: FailureStage?`
- `progressLabel`，用于“等待网络”“正在下载”等状态。

恢复动作直接由 `failureStage`、当前格式列表及输入状态推导，因此没有新增冗余的 `canRetry` 字段。

`DownloadWorker` 输出键增加：

- `KEY_OUTPUT_URI`
- `KEY_OUTPUT_NAME`
- `KEY_OUTPUT_RELATIVE_PATH`
- `KEY_FAILURE_STAGE`

输出值很小，符合 WorkManager `Data` 10 KB 限制；媒体直链仍通过现有私有请求缓存传递。

## 4. 文件级实施顺序

1. `DownloadWorker.kt`
   - 返回结构化 MediaStore 结果。
   - 区分下载与保存失败。
   - 为完成通知增加打开视频的 `PendingIntent`。
2. `DownloadRequestStore.kt`
   - 为当前任务恢复保留必要快照。
   - 明确成功、失败和取消后的清理时机。
3. `MainViewModel.kt`
   - 增加粘贴并分析入口、错误恢复动作和完成结果。
   - 持久化并恢复活动 Work UUID。
4. `HomeScreen.kt`
   - 压缩输入框、支持 IME、整行选择格式。
   - 合并状态区域。
   - 增加打开视频、查看位置、重试和再次下载操作。
5. `MainActivity.kt` 或独立 `MediaActions.kt`
   - 集中处理打开视频、文件位置和兼容回退，避免 Intent 逻辑散落在 Composable 中。
6. 单元测试与真机回归
   - 先验证状态转换和输出数据，再生成签名 Release APK 做 USB 真机测试。

## 5. 测试与验收

### 自动化

- 粘贴有效单链接会触发一次且仅一次分析。
- 手动输入不会在每次字符变化时请求分析。
- 格式行点击与 RadioButton 点击得到相同选择结果。
- Worker 成功结果包含 URI、文件名和相对路径。
- 分析失败、下载失败和保存失败映射到正确恢复动作。
- 已保存 Work UUID 能在 ViewModel 重建后恢复观察。
- 取消或终态后不会继续显示过期活动任务。

### 真机

- 375dp 级小屏、当前测试手机竖屏和横屏无横向溢出。
- 系统分享进入后自动分析，粘贴后自动分析。
- X 与 Threads 完成后“打开视频”可播放画面和声音。
- “查看位置”能打开文件管理器；不支持定位的设备能看到路径并进入文件选择器。
- 下载过程中切后台、锁屏、旋转和重启 App 后进度可恢复。
- 下载完成通知能打开视频或回到完成状态。
- TalkBack 能读出输入、格式选择、进度、打开视频和错误恢复操作。
- Release 构建、签名校验、同签名覆盖安装和 AndroidRuntime 崩溃检查通过。

## 6. 完成定义

以下条件全部满足后，里程碑 5.4 才标记为真机验收完成；当前代码实施已完成：

- 高频粘贴下载路径不超过两次主要点击。
- 状态和错误不重复显示。
- 下载成功后可以打开视频，并始终能获知保存路径。
- 当前下载任务在 App 重建后可恢复。
- X、Threads 的签名 Release 真机回归通过；Instagram 至少验证公开可访问样本或明确记录源站登录限制。
- 不新增广泛存储权限、后台剪贴板读取、账号或云服务器依赖。
