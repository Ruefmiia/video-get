# Android 下载溯源：精简来源记录

> 2026-10-03：开发版本 `1.1.0`（versionCode 5）。已接入下载与记录界面，单元测试、Debug APK 和设备测试 APK 构建通过。当前没有连接 Android 设备，数据库设备测试和签名 Release 真机验收尚未执行。正式内部发布基线仍为 `1.0.0`。

## 范围与字段

每次下载任务作为一组，只在媒体成功写入系统媒体库或 App 专属目录后记录。一个帖子中的多视频、轮播图片和混合媒体共享同一条来源组。失败或取消的项目不写入记录；取消前已保存成功的文件仍保留来源。再次发起下载形成新组，以对应实际生成的新文件。

| 来源组 | 文件记录 |
|---|---|
| ID（沿用 WorkManager 任务 ID） | 来源组 ID |
| 规范化原帖 URL | 文件名 |
| 下载时间（本次任务开始时间） | 文件 URI（主键） |

同一个文件 URI 重复写入不会产生重复记录。下载时间在同组第一次保存时写入，后续文件沿用；失败任务没有来源组。原帖 URL 沿用现有 URL 路由，去掉已知分享跟踪参数，保留 YouTube 视频 ID 和 Threads 分享链接等必要信息。分享页最终帖子链接未持久化时，保存可访问的规范化分享链接。

不保存标题、缩略图、媒体 CDN 直链、文件大小、媒体类型、失败详情、Cookie 或访问令牌。不复制媒体，不计算哈希，不修改文件内元数据，不为每个文件生成附属说明文件。来源记录只说明下载入口，不证明原创作者或版权归属。

## 轻量实现

- 使用 Android 自带 `SQLiteOpenHelper`，无需 Room 或新增数据库依赖。
- 数据库位于 App 私有数据库目录 `source-history.db`，两张小表及必要的查询索引。
- Worker 每成功保存一个文件，即用事务写入组和文件记录；部分成功立即可追溯。
- 数据库异常不丢弃已下载媒体，完成状态提示“部分来源记录保存失败”。
- 首页右上角“下载记录”入口，列表按时间倒序，每页 30 组；进入详情才加载该组的文件。
- IO 操作在后台线程执行，列表不加载媒体或缩略图。记录页支持手动刷新。
- 卸载 App 会删除来源数据库；同签名覆盖安装保留数据库。媒体被移动或删除不会清除来源记录。

## 界面与导出

记录列表显示文件名、推断的平台、下载时间和文件数量。详情提供打开原帖、复制链接、打开各文件及导出本组。文件不可访问时提示已移动、删除或缺少打开应用，仍保留原帖 URL。

列表支持“导出全部”，详情支持“导出”。系统文件保存窗口使用 `ACTION_CREATE_DOCUMENT`，用户选择文件位置，无需额外存储权限。CSV 为 UTF-8 BOM，三列：`原帖 URL、下载时间、文件名`。每个文件占一行，时间包含时区；不导出设备专用 URI。逗号、换行、引号按 CSV 规则转义，公式式文件名加文本前缀，便于 Excel 安全查看。

导出使用数据库游标和缓冲 Writer 直接写入目标，不把全部记录读入内存，不在 App 中留导出副本。保存后可由文件管理器分享 CSV。第一版不含 JSON、导入、云同步或自动补录旧版下载。

## 验证与真机验收

自动化覆盖：CSV 中文与 BOM、转义和公式式文件名；Android 数据库测试覆盖多文件归组、去重、重新打开持久化、倒序分页、单组/全部导出及拒绝 CDN URL。

```powershell
cd D:\Codex\video-get\apps\android
.\gradlew.bat testDebugUnitTest assembleDebug assembleDebugAndroidTest
# 在单独的 Debug 测试设备/模拟器上运行（需要安装 Debug 签名包）：
.\gradlew.bat connectedDebugAndroidTest
```

真机重点：

1. X、Instagram、Threads、YouTube 各成功下载一次，原帖 URL 与保存文件相符。
2. 多视频、轮播、图片/视频混合帖只形成一个组，成功文件均能打开。
3. 下载部分失败或取消后，已成功文件仍可查；失败项不生成空记录。
4. 退出并重开 App、重启手机后记录保留；同签名覆盖安装原版登录会话保持。
5. 导出单组与全部 CSV，Excel 显示中文、链接、文件名正常；取消文件选择器后仍能再次导出。
6. 移动/删除媒体后打开文件得到明确提示，原帖仍可打开和导出。
7. 小屏、横屏、大字体、浅色/深色模式下按钮与文件名可用。
