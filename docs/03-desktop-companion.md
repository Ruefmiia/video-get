# 阶段 3：Windows 桌面辅助程序

## 目标

让非技术用户不必安装 Python、FFmpeg 或使用命令行，即可运行浏览器扩展依赖的本地下载服务。

第一版以 Windows 为目标；macOS/Linux 只保留可移植设计，不承诺安装包。

## 职责

- 安装应用自身、Python 运行时和下载核心。
- 安装并验证 FFmpeg/ffprobe。
- 启动单实例本地 API。
- 生成并保护本地 API 令牌。
- 提供托盘菜单、运行状态、日志入口和下载目录入口。
- 检查更新，但不静默替换正在运行的下载核心。
- 完整卸载程序文件；用户下载文件默认保留。

## 建议实现

两种方案均可：

1. Python 打包：PyInstaller/Nuitka 打包启动器与 FastAPI。
2. 小型原生启动器：Rust/Tauri 或 .NET 管理 Python 服务。

第一版优先选择团队最熟悉的方案。安装器可采用 Inno Setup、WiX 或 MSIX，但必须支持签名和干净卸载。

## 运行约定

- 默认端口：`17382`。
- 仅监听 `127.0.0.1`。
- 已有实例运行时，第二次启动只打开状态页或托盘菜单。
- 端口占用时不得自动监听公网；可以选择受控备用端口，并通过 Native Messaging 告知扩展。
- 后台服务异常退出时有限次数重启，连续失败后停止并显示诊断。
- 安装目录、数据目录、临时目录和下载目录分离。

## 本地鉴权

- 首次安装生成至少 256 位随机令牌。
- 令牌存储在当前用户可读的受限位置，不能打包为固定值。
- 扩展通过安装引导或 Native Messaging 获得令牌。
- 每个请求校验 `Authorization: Bearer <local-token>`。
- `/health` 可匿名访问，但只返回 `{"status":"ok"}`。

## FFmpeg 管理

- 启动时校验 `ffmpeg -version` 和 `ffprobe -version`。
- 记录实际二进制版本和来源。
- 使用受信任的固定下载源与校验和。
- 下载/更新失败时不覆盖上一份可用版本。
- 对不同许可证构建进行记录，并在发行包中附带第三方许可证。

## 更新策略

更新清单至少包含：

- 桌面程序版本
- API 兼容版本
- yt-dlp 版本
- FFmpeg 版本
- 包 SHA-256
- 签名信息

yt-dlp 更新应可独立于 UI 更新，但必须经过冒烟测试和回滚机制，不能每次启动无条件拉取最新版。

## 日志与诊断

提供“复制诊断信息”，包含：

- 应用/API/yt-dlp/FFmpeg 版本
- 操作系统版本与架构
- 本地端口是否可用
- 数据库是否可写
- 下载目录是否可写
- 最近错误码

不得包含 Cookie、Authorization、完整媒体签名 URL或用户文件名列表。

## 卸载行为

- 删除应用、运行时、缓存和注册项。
- 默认保留下载文件与历史数据库，并明确提示位置。
- 用户勾选“同时删除应用数据”时再移除数据库和日志。
- 卸载前停止明确识别的本程序进程，不按模糊名称终止其他进程。

## 完成标准

- 全新 Windows 环境可以一次安装后使用扩展。
- 不需要用户预装 Python 或 FFmpeg。
- 开机启动为可选项，默认行为在安装界面说明清楚。
- 端口冲突、FFmpeg 缺失、数据库损坏均有可操作的诊断。
- 卸载后无残留后台进程，用户下载文件未被误删。
- 安装包、更新包和第三方许可证清单可重复生成。
